# 0.8.0: instant admission

Status: proposal, 2026-10-15. Supersedes the automatic capacity check and the
trip-and-cool-down state machine described in `docs/capacity.md` (0.7.x).
Line references are to the `feat/engine-selection` branch at `ab0b0e2`.

## Decision summary

The kernel already protects the call: `memory.max` with no swap and
`oom_score_adj=1000` on the engine host (engine_host.py:247-251) kills the
engine before Talk, `cpu.max` bounds it, `cpu.weight 10` starves it first
under host contention. 0.8.0 stops re-implementing that in Python.

- **Start = fit check + load.** `pool.start()` runs as soon as the container
  has finite limits and `non-reclaimable memory + engine RSS + allowance <=
  memory.max`. `state` goes `blocked -> loading -> ready` in load time
  (Nemotron 1.2-1.9 s warm, specs.md:48; up to `start_timeout_s` cold). The
  outcome future resolves at ready, so switch, rollback, restore and restart
  all cost one load, not ~85 s of synthetic scenarios.
- **Admission per speaker, by identity.** A `LoadGovernor` (new
  `cassini_live/load.py`) decides at the moment a speaker needs a worker or
  slot (transcriber.py:148, :362). The first speaker is always admitted. A
  further speaker is admitted when the structural ceiling has a free seat,
  memory headroom covers two more speakers, container CPU stall is below
  threshold and the live transcription lag is below `LAG_ADMIT`. Admitted
  speakers keep their seat; closing admission never evicts them (this fixes
  the count-based ratchet all three drafts had).
- **Continuous shedding.** `lag_sustained` (5 s rolling minimum of per-second
  maxima, the harness definition in local/stt-eval/resources/rt_common.py:19-22)
  above `LAG_SHED` pauses the newest admitted stream: its transcriber ends the
  segment, frees the slot, shows a non-final "captions paused" preview line
  and stays out for a hold-off. Rooms, tracks and other speakers are untouched.
- **Trip only on a real crash.** OOM kill (`memory.events oom_kill` delta) and
  the backends' 3-in-60 s failure circuit, with the unchanged journal and
  `RecoveryPolicy` back-off (120 s base, 3600 s cap). A single non-OOM host
  death still restarts in place (1-2 s); a late reply from a live host is no
  longer a failure.
- **Measurement on demand.** `CapacityAssessment` and `calibration.scenario`
  stay as an administrator-triggered run (settings page button and container
  CLI), never automatic. It reports lag per speaker count; its result is
  displayed, never used as a gate. The room cap derived from `testedSpeakers`
  is replaced by the live admitted count.
- **Instrumentation first.** Steps 1-4 ship to staging with the governor in
  observe-only mode; `LAG_ADMIT`, `LAG_SHED`, `CPU_STALL_ADMIT` and the
  per-speaker memory allowance are fixed from that run (bounded today by the
  harness table in local/stt-eval/resources/results.md) before step 5 lands.

## Admission rule

Decision point: `await self.pool.admit(self)` before `acquire_slot` /
`acquire_wait` in both `_decode_audio` paths, i.e. at the start of a gate
segment. `admit` is `LoadGovernor.admit(transcriber)`, installed on every
backend by `SafetyController._hook` (where `resource_check`/`load_check` are
installed today, safety.py:101-103). Pure, in-memory, O(transcribers <= 12).

The governor keeps `seats: dict[transcriber -> admitted_at]` (WeakKeyDictionary).

1. `transcriber.paused_until > now` -> refuse (`Shed`): chunk dropped, no wait.
2. `transcriber in seats` -> **admit** (seat holders are never refused; the
   FIFO hand-off among seat holders, bounded by `pool.size`, is unchanged).
3. `not seats` -> **admit** (first speaker always), take a seat.
4. `len(seats) >= ceiling` -> refuse, reason `ceiling`.
5. memory: `headroom_mib < 2 * per_speaker_mib` -> refuse, `memory`.
6. CPU: `cpu_stall >= CPU_STALL_ADMIT` -> refuse, `cpu`. Skipped when PSI is
   unavailable (no longer a blocking configuration error).
7. host memory: `hostAvailableBytes < max(256 MiB, 10 %)` -> refuse,
   `host_memory` (inherited, flagged, hold only).
8. lag: `lag_now >= LAG_ADMIT` -> refuse, `lag`.
9. otherwise **admit**: take a seat, `admitted_at = now`.

A refused speaker still parks in the existing bounded FIFO wait (2 s Whistle /
`SLOT_WAIT_S` 4 s Nemotron) so a seat freed by a track closing is handed over
at once; on timeout the existing `CapacityError` branch (transcriber.py:229-233,
:401-404) drops the chunk, counts `capacity_waits`, and now also sends the
"captions paused" preview (at most once per `NOTICE_INTERVAL`) and sets
`paused_until = now + HOLD_OFF` when the reason was `lag` or `cpu` (a memory
or ceiling refusal retries at the next segment).

Seats are released when the track closes (`abort`/`_release` on connection
close), when the transcriber is shed, or after `SEAT_IDLE_S` without a lease.
Because `admit` is the only gate and `len(seats) <= pool.size`, the pools'
`admission_limit` stays equal to `size`; `status()["admittedSpeakers"]`
becomes `len(seats)`. `pool.kick()` (Whistle: idle workers to waiters;
SharedEngine: `_offer()`) runs from the tick whenever the governor reopens so
a parked waiter is not left until the next release (pool.py:139-148,
shared.py:229-234 only hand out below the limit).

Hysteresis: the governor is `closed` from the first refusal for `lag` or `cpu`
and reopens when `lag_sustained < LAG_ADMIT / 2` and `cpu_stall <
CPU_STALL_ADMIT / 2` for one full window.

Rooms: `allow_room(rooms)` becomes `require_ready()` plus `len(tracks) <
max_tracks` and `not measuring`. No room-level refusal by load: the decision
is per speaker, so a room opens even while the governor is closed and its
first speaker is refused with the preview notice rather than an HTTP 503.
`max_tracks=10`, `MAX_STREAMS=12` and the 64-room cap stay as hard ceilings.

Structural ceiling: `catalog.worker_ceiling` returns 3 on staging (2 CPU,
`engine_threads` 1) while the harness fails every 3-speaker cell at one thread
(results.md:118,120,133,135: lag 4.2-6.6 s, 11-103 would-drop chunks) and
passes 4 speakers at two threads (results.md:123,138). 0.8.0 re-derives the
Nemotron ceiling as `min(4, 2 * engine_threads)` with that provenance (owner
decision, see open questions); the staging 1.0x run may loosen it.

## Shedding

Evaluated by `LoadGovernor.tick()` every 1 s from `SafetyController._watch`;
acted on **inside the transcriber's own task** (no cross-task preemption of an
in-flight `engine_stream.audio()`; a commit from another task would raise
`Superseded` into it, shared.py:306-307).

1. `lag_sustained >= LAG_SHED` and at least two seat holders have a lease and
   `now - last_shed >= SHED_INTERVAL` -> choose the seat holder with the
   latest `admitted_at` that holds a lease; remove its seat; set
   `transcriber.shed_reason`; `last_shed = now`; `shed_events += 1`; one
   WARNING with lag, seats, reason.
2. The transcriber checks `shed_reason` at the top of the next piece in
   `_decode_audio` (next to the Whistle 2 s preemption test, transcriber.py:158,
   :191): Whistle `_finish("shed")` ends the lease; Nemotron `_finish("shed")`
   commits and releases the slot, the native stream stays open (shared.py:5).
   Then `paused_until = now + HOLD_OFF`, `stream_ends["shed"] += 1`, preview
   set to the notice. While paused, `_decode` drops chunks via `_note_drop()`
   without engine traffic.
3. Notice: `Transcript(final=False, language, "Captions paused for this
   speaker while the server catches up", session_id)` on the room queue,
   delivered by `send_transcript` (talk/client.py:564-591) as that speaker's
   preview; the next partial replaces it, nothing lands in Talk's transcript
   history. Every caption viewer in the room sees it under that speaker's name;
   there is no per-participant channel (accepted; verified in a browser on
   staging before relying on it).
4. Resume: after `paused_until` the speaker goes through `admit()` as a new
   speaker (newest seat, fair) and is admitted only when the governor is open.
5. A single seat holder is never shed. Memory, CPU and host-memory inputs
   close admission only; they never shed (PSI is slow and cannot see a single
   decode thread saturating: results.md:120 shows 0.98 duty with 0.19 s
   throttled). Memory above the limit is the kernel's OOM, handled as a crash.
6. The existing chunk-level bounds stay as the last line: queue `maxsize=6`,
   4 s stale cut, 2 s/4 s waits. `LAG_SHED` is derived to sit under them.

## Crash handling

Trips: `trip()` keeps `failures += 1` when ready, `recovering/cooling_down`,
`next_attempt = now + RecoveryPolicy.delay(failures)` (120 s * 2^(n-1), cap
3600 s, 0-20 % jitter), `last_trip`, journal persist, `_teardown` (pool.close,
`service.stop_rooms()` within 30 s else `fatal_exit(75)`, lease release).
`insufficient` and the 300 s floor go. `stable_window` 600 s resets
`failures` (kept, flagged unjustified; a derived "ready longer than the delay"
rule would cap a periodic OOM loop at a permanent 120 s cadence).

Triggers, exactly two:

- **OOM kill.** The tick reads `oomKills`; a delta trips with "The caption
  memory limit was exceeded". Single owner of the restart: the backend's
  pre-spawn hook (renamed `start_check`, consulted at shared.py:396 and, new,
  in `WorkerPool._new` in place of `resource_check`) refuses when the **live**
  `oomKills` exceeds the value recorded at the last successful ready (not the
  governor's last tick, so tick ordering cannot let a restart through), or
  when the fit check fails. A refused restart opens the circuit (existing
  shared.py:371-374); the tick trips on it. No second model load inside an
  OOM-ing container. `pool.close()` must cancel `_restart` and a starting host
  (shared.py:445-449 already does).
- **Failure circuit.** 3 host/worker failures in 60 s (pool.py:215-218,
  shared.py:347-350). A single non-OOM death keeps today's in-place restart
  (1.2-1.9 s warm) with streams reconnecting on the next chunk
  (transcriber.py:405-411); the journal counts it as a failure, no rooms
  close.

What is no longer a failure: a **late reply** from a live host. `_request`'s
5 s timeout (shared.py:313-316) calls `_host_failed` only when
`host.returncode is not None` or the host has emitted nothing at all for
`HOST_SILENCE_S`; otherwise it raises `EngineStreamError("late")` for that
request, the transcriber drops the chunk and reopens its stream at the next
one, and the host stays up. Under `cpu.weight 10` starvation three late
answers in a minute must not close every room for two minutes.

Load failures (`pool.start` raising, `start_timeout_s`) still trip with the
error text so `engine_switch._rollback` and `_watch_restore` keep their
"first load failed" semantics. A fit-check refusal **before** a load is not a
failure: `blocked/configuration` with "Not enough memory to load X", polled
every 15 s, `adminActionRequired`.

Boot: journal crash detection unchanged (`engineRunning` without
`attemptInProgress` -> failures+1, safety.py:225-230); `attemptInProgress`
now spans only the load; `fresh=True` on admin switches still resets
failures/next_attempt. Limit changes no longer trip (`signature()` deleted):
the next tick simply reads the new numbers.

## Migration from 0.7.2

- Journal file and keys unchanged; a 0.7.2 file reads as-is. Boot rules: (a) a
  journal without `appVersion` (written by 0.7.x), with neither `engineRunning`
  nor `attemptInProgress` set, whose `reason` names a trip 0.8.0 removed (the
  capacity check, CPU quota stalls, host CPU pressure, the event loop falling
  behind, resource limits changed, memory or PID budget nearly exhausted, host
  memory pressure or headroom, unreadable pressure counters, the load-time
  memory estimate) resets `failures=0`, `nextAttemptAt=0`, clears `lastTrip`
  and persists (a 5 min "insufficient" cooldown from 0.7.2 cannot delay the
  first 0.8.0 start). `lastTrip.reason` is never matched: it outlives a crash a
  later boot detected ("Recovering after an interrupted caption process"), and
  the persisted journal carries `appVersion`, so a second boot during a real
  crash cooldown cannot forgive it; (b) `attemptInProgress=true` with a journal
  `appVersion` different from the running version (new optional field, ignored
  by older readers) is cleared, so a container stopped mid-check by the upgrade
  is a clean restart; (c) every other future `nextAttemptAt` is honoured, cap*1.2
  clamp kept: an OOM kill ("The caption memory limit was exceeded"), the failure
  circuit ("Repeated recognition worker failures"), a crash while running or
  loading (`engineRunning`, "Recognition workers or resource monitoring
  failed", "Recovering after an interrupted caption process"). All branches
  logged and tested.
- `cassini-live-settings.json` unchanged; `last_error` codes `capacity_failed`
  / `timeout` parse (scalars) and render through the legacy text; `restore()`
  clears a `capacity_failed` error; `pending` from an interrupted switch still
  becomes `interrupted`.
- Unhardened AppAPI start: `memory.max` = `max` -> `start_problem` returns "Set
  finite cgroup v2 memory limits" -> `blocked/configuration`, 15 s poll, no
  engine, same message as 0.7.2; `restore_deferred` keeps the Nemotron choice
  with Whistle active (also blocked). After `harden-container.py` recreates
  the container, `restore()` clears the deferral and Nemotron is ready in
  seconds. `_watch_restore` rolls a restored engine back to Whistle only when
  its first load fails; never on a later trip.
- Version 0.8.0 in `appinfo/info.xml` and `__version__` (AppAPI re-reads
  routes on a version change). `scripts/check_deployment.py` reads
  `enabled`/`signallingConfigured`/`workers` only; unaffected. Document in
  codemyriad-systems that "wait for the capacity result" is gone and health
  checks may read `resourceSafety.admission`.

## Decisions (Silvio, 2026-10-16)

All six questions answered "yes to all" to the recommendations:

1. **Whistle two-room clamp**: dropped. Seats and the 2 s hand-off bound Whistle.
2. **Nemotron ceiling**: `min(4, 2 * engine_threads)` (staging: 2 seats until a
   1.0x run says otherwise).
3. **Circuit trip** (3 host deaths in 60 s) still closes every room; revisit if
   it ever fires in practice.
4. **Paused notice** as a preview line under the speaker's name, visible to
   every caption viewer in the room, until Talk offers a per-participant channel.
5. **Static installation rules**: only finite cgroup v2 limits, swap 0 and the
   measured memory floor stay blocking; half-host CPU/memory and `pids <= 256`
   become settings-page advice.
6. **Host-memory hold input**: dropped; the kernel limits stand alone.

as **0.7.3** (no behaviour change); the behaviour (steps 5-11) ships as
